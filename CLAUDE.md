# DIGEX Campus — инструкции для Claude Code

Образовательная платформа (Claude и ChatGPT). Стек: React + TypeScript strict, Vite, React Router, SCSS,
lucide-react, Supabase Auth + PostgreSQL. Подробности — README.md.

## Общие правила

- Работать небольшими этапами; после каждого этапа остановиться для проверки владельцем проекта.
- Не использовать `any` и `@ts-ignore`; не добавлять лишние зависимости.
- В браузерный код — только publishable-ключ Supabase. Не читать и не выводить `.env.local`, не просить секретные ключи.
- Демо-данные только в режиме разработки (`VITE_DEMO_MODE=true` в `npm run dev`); в обычном режиме не подставлять их никогда.
- SQL-изменения — только миграциями в `supabase/migrations/`. Не выполнять SQL в удалённой базе и не менять настройки Supabase без отдельной задачи.
- Не делать commit, push и deploy без явной просьбы.

## Независимое ревью после каждого этапа

Процесс описан в `docs/review-process.md`.

1. Сначала выполнить проверки, создающие build/cache-файлы: `npm run typecheck`, `npm run lint`, `npm run build`.
2. Затем запустить read-only ревью Codex: `npm run review:codex` (или всё сразу: `npm run verify`).
   Перед ревью обновить `.codex/review-prompt.md` под проверяемый этап. Одновременно — только одно ревью.
3. Код 0 не означает «замечаний нет»: прочитать отчёт `reports/codex/codex-review.md` (и датированный отчёт рядом).
   При ошибке запуска не использовать старый отчёт как новый.
4. Исправить подтверждённые P0/P1/P2; при несогласии — привести конкретное обоснование.
5. Повторить проверки и ревью. Не более трёх циклов за запуск; если проблемы остаются — остановиться с точным отчётом.
6. Сообщить владельцу: версию Codex, результаты проверок, замечания и исправления, путь к отчёту, что не проверено.
