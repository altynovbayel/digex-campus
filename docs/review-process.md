# Процесс независимого ревью

| Роль | Кто | Что делает |
|---|---|---|
| Разработчик | Claude Code | Реализует этап, запускает проверки, исправляет замечания |
| Ревьюер | Codex CLI | Только читает проект и пишет отчёт; файлы приложения не меняет |
| Владелец проекта | человек | Принимает результат этапа и решения по спорным замечаниям |

## 1. Порядок после каждого этапа

```text
реализация этапа
  → npm run typecheck / lint / build      (Claude; создают build/cache-файлы)
  → npm run review:codex                  (Codex, read-only)
  → Claude читает отчёт и решает по каждому замечанию:
       принято → исправление; отклонено → конкретное обоснование
  → повторные проверки и ревью изменённых мест
  → отчёт владельцу
```

Правила:

- Код возврата 0 означает только, что отчёт получен и прошёл проверки. **Отчёт нужно прочитать.**
- Подтверждённые P0/P1/P2 исправляются; P3 — по усмотрению. Несогласие обосновывается ссылками на код или документацию.
- Не более трёх циклов «ревью → исправления» за один запуск. Если проблемы остаются — остановиться и описать их владельцу.
- Никаких коммитов, push, deploy, SQL в удалённой базе и изменений настроек Supabase без отдельной задачи.
- Одновременно выполняется только одно ревью; бесконечных повторов нет.

## 2. Команды

```bash
npm run verify        # typecheck → lint → build → review:codex (останавливается на первой ошибке)
npm run review:codex  # только ревью, задание .codex/review-prompt.md
scripts/codex-review.sh path/to/task.md   # ревью с другим заданием (например, повторная проверка)
```

Сборка и проверки, создающие файлы (`dist/`, `node_modules/.tmp`), выполняются **до** ревью:
во время ревью скрипт проверяет, что файлы проекта не изменились.

Переменные окружения (действуют только на один запуск, конфигурация Codex не меняется):

| Переменная | По умолчанию | Значение |
|---|---|---|
| `CODEX_REVIEW_EFFORT` | `high` | `model_reasoning_effort` через `-c` |
| `CODEX_REVIEW_MODEL` | выбор CLI | `--model` |
| `CODEX_REVIEW_TIMEOUT` | `1800` | предел времени, секунды |
| `CODEX_REVIEW_KILL_GRACE` | `10` | ожидание между TERM и KILL, секунды |
| `CODEX_BIN` | `codex` из PATH | путь к CLI |

## 3. Как запускается Codex

Флаги сверены со справкой `codex exec --help` версии **0.167.0**. После обновления CLI сверить заново.

| Флаг | Зачем |
|---|---|
| `exec` | неинтерактивный запуск |
| `--sandbox read-only` | команды Codex не могут менять файлы |
| `--cd <корень проекта>` | рабочий каталог |
| `--ignore-user-config` | личный `~/.codex/config.toml` не влияет на ревью (вход сохраняется) |
| `--ephemeral` | сессия не сохраняется на диск |
| `--color never` | читаемый лог |
| `-c model_reasoning_effort="high"` | глубина рассуждений |
| `--output-last-message <файл>` | итоговое сообщение — будущий отчёт |
| `-` | промпт читается из stdin |

Опасные флаги (`--dangerously-bypass-approvals-and-sandbox`, `danger-full-access`, `--add-dir`) не используются.
Codex получает очищенное окружение (`env -i`): переменные приложения из оболочки ему не передаются.

## 4. Когда отчёт принимается

Скрипт принимает отчёт только если одновременно:

1. `codex exec` завершился с кодом 0 и не по таймауту;
2. в заголовке лога подтверждены `sandbox: read-only` и запрошенный effort;
3. среди выполненных Codex команд нет обращений к `.env`-файлам (кроме `.env.example`), `reports/`, конфигурации Codex,
   а также `rg --no-ignore/-uu` и `grep -r` (они могли бы прочитать `.env.local`);
4. хэш файлов проекта (без `.git`, `reports`, `node_modules`, `dist`) не изменился;
5. новый отчёт не пуст и заканчивается маркером `<!-- CODEX_REVIEW_COMPLETE -->`;
6. в отчёте нет похожего на ключ, токен, адрес проекта Supabase или email текста (кроме доменов `example.*`).

При любой ошибке выводится причина, создаётся `.meta` со статусом, а **последний принятый отчёт не обновляется** —
старый отчёт нельзя выдать за новый.

## 5. Файлы

```
.codex/review-prompt.md            задание ревью по умолчанию (в Git)
scripts/codex-review.sh            запуск и проверки (в Git)
reports/codex/                     НЕ в Git
  <дата>_<id>_<задание>.md         принятый отчёт
  <дата>_<id>_<задание>.log        полный лог codex exec (диагностика)
  <дата>_<id>_<задание>.meta       версия, модель, effort, sandbox, код выхода, статус
  <дата>_<id>_<задание>.prompt.md  фактически отправленный промпт
  codex-review.md                  копия последнего принятого отчёта
  .lock                            признак выполняющегося ревью
```

Если запуск был убит без очистки и остался `reports/codex/.lock`, убедитесь, что `codex exec` не выполняется, и удалите каталог вручную.

## 6. Секреты

- Codex по заданию не читает `.env.local`, `.env.*` (кроме `.env.example`), учётные данные и `reports/`; это проверяется по логу команд.
- Ограничение: sandbox read-only запрещает запись, но не чтение. Защита от чтения — правила промпта, `.gitignore`
  (rg его соблюдает) и аудит выполненных команд после запуска. Если аудит сработал, лог может содержать секреты —
  просмотрите и удалите его.
- Содержимое секретных файлов не передаётся в промпт и не попадает в отчёты.
