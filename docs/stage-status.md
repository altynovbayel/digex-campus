## Показ пароля и мобильная адаптация (2026-11-20)

### Показ пароля
- Кнопка с иконкой глаза внутри каждого поля пароля: вход, регистрация (пароль и повтор), новый пароль (оба поля).
- По умолчанию пароль скрыт; поля переключаются независимо; `type="button"` — форму не отправляет, значение не очищает;
  названия «Показать пароль» / «Скрыть пароль»; видимый фокус (в т. ч. в режиме принудительных цветов); область 44×44 px.
- Пароль снова скрывается при отправке и сбросе формы и когда поле становится пустым — после неудачного входа следующий
  пароль вводится скрытым. Кнопка всегда доступна (фокус не теряется). `autocomplete` сохранён; при показе отключены
  автоисправление и заглавная буква.

### Причины переполнения на телефоне и исправления
| Причина | Исправление |
|---|---|
| `.sr-only` в заголовках таблиц выходил из области прокрутки `.table-wrap` (нет `position: relative`) — админка шириной 462–676 px при экране 375 px | `position: relative` у `.table-wrap`; таблицы прокручиваются в своей области |
| Шрифт полей 15 px — iOS Safari приближает страницу при фокусе на поле | 16 px при `(max-width: 959px), (pointer: coarse)`; на компьютере прежние 15 px |
| `100vh` у мобильного меню и каркаса — низ меню под панелью Safari | `height: auto` / `100dvh`, `overscroll-behavior: contain` |
| Безопасные зоны iPhone не учитывались | `viewport-fit=cover` + `env(safe-area-inset-*)` в шапке, меню, контенте, подвале, формах входа, уведомлениях |
| Длинные слова (email, названия, URL) растягивали flex/grid-блоки | `overflow-wrap: break-word`; точечно `anywhere`, `min-width: 0`, `minmax(0, 1fr)` |
| Подпись недоступной кнопки в админке на 320 px | перенос на узком экране |

Глобальный `overflow-x: hidden` не используется; масштабирование не запрещено.

## Этап 3Б: что реализовано

- Один тест на урок, вопросы с 4 непустыми вариантами и одним правильным, 1 балл за верный ответ.
- Ученик получает тест без правильных ответов (`get_quiz`); баллы считает только база (`submit_quiz_attempt`):
  проверка доступа, публикации, версии теста, принадлежности и полноты ответов; повтор запроса не создаёт дубль.
- Попытка хранит снимок вопросов и ответов: правка теста не меняет прежние результаты. Ученик читает свою историю
  (баллы и проценты), но не снимок `answers` с ключами ответов; администратор — через `admin_attempt_answers`.
- Показатели (`my_quiz_stats`): пройдено тестов, попыток, средний результат (по последней попытке каждого теста),
  прогресс по опубликованным тестам.
- Администратор: редактор тестов («Разделы и уроки» → «Тест») — только через функции базы с единым порядком
  блокировок и проверкой версии; «Результаты» с фильтрами по ученику, разделу и уроку.

## Известные ограничения

- **Взаимные блокировки при перестановке уроков** (принято владельцем, не исправляется): возможны при двух
  одновременных перестановках уроков раздела во время добавления урока в этот раздел, а также при обновлении
  нескольких уроков одним прямым запросом к API. PostgreSQL прерывает одну операцию (`40P01`), данные не портятся.
- Конкурентные сценарии проверены анализом кода и ревью, а не параллельными транзакциями (PGlite — одно соединение).
