# Ревью DIGEX Campus: этап 3Б — тесты, попытки, результаты и прогресс

## Контекст

DIGEX Campus — образовательная платформа (React + TypeScript strict + Vite, Supabase Auth и PostgreSQL). Роли: student, admin.
Согласованная бизнес-логика (не меняется): Claude и ChatGPT — два раздела одного курса; одна оплата открывает оба на общий
срок 14 суток; назначений по группам нет; после окончания или отзыва материалы и новые тестирования закрыты,
профиль и ранее полученные результаты сохраняются.

Уже применены в настоящей базе и **не должны меняться**: `20261117000000_profiles.sql`, `20261118000000_learning.sql`,
`supabase/seed/initial_content.sql`, `20261119000000_course_access.sql`.
Этап 3Б — новая миграция `supabase/migrations/20261120000000_quizzes.sql` и наполнение `supabase/seed/quizzes.sql`
(генерируется `scripts/generate-quiz-seed.mjs` из `src/data/lessons.ts`).

## Требования (проверь соответствие)

1. Тест: один на урок; несколько вопросов; 4 непустых варианта; один правильный; 1 балл за верный ответ.
   Администратор создаёт и редактирует вопросы и варианты, выбирает правильный, меняет порядок, публикует и снимает.
   Пустой или некорректный тест публиковать нельзя.
2. Прохождение при действующем общем доступе: опубликованный тест опубликованного урока; по одному ответу;
   отправка после ответа на все вопросы; количество верных и процент; повторное прохождение.
   Нет проходного балла, лимита попыток, таймера, блокировки уроков. Блокировка повторного нажатия; повтор одного
   запроса не создаёт две попытки; новая осознанная попытка — отдельно. При ошибке — нет ложного успеха и ответы
   не теряются, если тест и сессия не изменились.
3. Оценка только в базе; клиент отправляет выбранные варианты; пользователь — по авторизации. Сервер проверяет:
   действующий доступ; публикацию урока и теста, отсутствие архива; принадлежность вопросов и вариантов тесту;
   полноту и отсутствие повторов; неизменность версии с момента загрузки (иначе — предложение загрузить заново);
   доступ, закончившийся до отправки. Ключи ответов не выдаются ученику до отправки — ни через таблицы/API,
   ни через JS-бандл; не только скрытыми полями. RLS и явные права; функции проверяют полномочия; без Secret key.
4. Попытки в базе: пользователь, урок, тест, дата сервера, ответы, верные, всего, процент; данные версии,
   чтобы правка вопросов не меняла старые результаты; история не удаляется при снятии с публикации.
   Профиль: история своих попыток (урок, раздел, дата, баллы, процент), сохраняется после перезагрузки и повторного
   входа, доступна после окончания или отзыва доступа без открытия материалов. Админка «Результаты»: фильтры
   по ученику, разделу, уроку; простая таблица.
   Показатели из базы: «Пройдено тестов» — уникальные тесты с попыткой; «Попыток» — все; средний результат —
   по последней попытке каждого теста; прогресс — уникальные пройденные из опубликованных тестов доступной программы.
   Попытки не называются изученными уроками. Честное пустое состояние.
5. Наполнение: по 3 содержательных вопроса к 12 урокам; повтор без дублей и без перезаписи правок; без вымышленных
   попыток; уроки и id сохраняются. Миграция сохраняет аккаунты, роли, разделы, уроки, оплаты.
6. Смена аккаунта во время запроса; изменение теста во время прохождения; окончание и отзыв доступа до отправки.
7. Совместимость с выключенным «Automatically expose new tables» и включённым автоматическим RLS (явные GRANT);
   SECURITY DEFINER-функции: безопасный search_path, ограниченный EXECUTE, явная проверка вызывающего.

Также отметь реальные ошибки корректности, гонки, доступности (label, клавиатура) и TypeScript (any, ts-ignore).

## Формат отчёта

1. **Итог** — 2–4 предложения.
2. **Замечания** — по убыванию приоритета. Для каждого: приоритет P0/P1/P2/P3, файл:строка, сценарий, последствия, минимальное исправление.
3. **Проверено без замечаний** — кратко, по пунктам требований.
4. **Следующий этап** — что не реализовано и не проверялось.
5. **Ограничения проверки** — что нельзя подтвердить чтением исходников (настоящий Supabase, PostgREST, SQL Editor,
   фактические данные и права в базе, поведение браузера и т. п.).
